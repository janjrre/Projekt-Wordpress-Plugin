# Alpha.2: PR #1 review corrections

Scope is limited to the five confirmed findings in M0/M1. Phase 3 > Phase 2 > Phase 1 remains authoritative. The manifest, all 28 table definitions and their indexes are unchanged. No M2 feature is added. Alpha.1 remains a separate historical artifact and must not be overwritten.

| Finding | Cause | Correction | Regression |
| --- | --- | --- | --- |
| P1: dbDelta loses its lock | dbDelta bypassed the adapter's reconnect protection. | The adapter now owns schema execution. Each dbDelta query checks original session identity and advisory-lock ownership. Reconnection is disabled throughout; strict driver exceptions stop lost-session queries before WordPress can replay or terminate them. Only the expected missing-table DESCRIBE error permits the original CREATE, still behind the fence. Driver mode, filters and connection settings are restored in finally. Failure reporting never overwrites a successor runner's state. | `PersistenceTest::test_lock_loss_during_dbdelta_never_replays_create_or_alter_and_can_resume`, separately for CREATE and ALTER: kill the original connection, acquire its lock from a second connection, assert no table/index change, unchanged checkpoint/version and successful later resume. |
| P1: two transaction managers can nest | The active flag belonged to the manager object. | A weak map keyed by the physical connection coordinates all adapters/managers. The inner attempt is rejected before START TRANSACTION; rollback and retries release the shared state. | `PersistenceTest::test_two_transaction_managers_share_physical_connection_ownership`, using both the same adapter and separate adapters over the same physical connection. No outer/inner rows remain. Existing complete-attempt deadlock retry, exhaustion and callback tests remain blocking. |
| P2: current version conceals schema drift | The runner verified only pending migrations; health trusted options. | Explicit activation/recovery verifies the installed schema and seed even at the current version. Site Health independently reads and verifies the actual schema, reports critical on failure, and exposes only safe exception class/code. Repair is explicit; current-schema verification does not silently change DDL. | `PersistenceTest::test_activation_recovery_and_health_reject_drift_at_current_version`: remove uq_org_wp_user, reject activation/recovery, report critical without SQL disclosure, restore the required index and recover successfully. |
| P2: cache invalidation before commit | Another request could repopulate old options during a transaction, or a read could cache uncommitted state. | Invalidation runs after commit and rollback and targets the options table's owning site. The small set of migration-owned options bypasses the shared cache, preventing uncommitted cache publication and rejecting stale fills that arrive after invalidation. No product data cache is introduced. | `CacheRegressionTest::test_commit_and_rollback_with_parallel_request_and_persistent_cache`: two PHP processes and DB connections share a file-backed options cache; barriers coordinate reads during the transaction and stale publication after completion. Both commit and rollback are checked. The fixture is excluded from release ZIPs. |
| P2: public packaging endpoint | The release included bin/package.php without a SAPI guard. | The packager refuses non-CLI execution with HTTP 403 before filesystem access. Development/build scripts are excluded from the release allowlist. | `php tests/packaging.php`: inspect the actual release ZIP and serve an isolated copy of the source script over HTTP; require empty 403 response and no files created. |

## Additional required verification

- All existing Unit/Architecture, Integration, CLI and browser tests remain enabled.
- CI runs PHP 8.3/8.4/8.5 against MySQL 8.0 and MariaDB 10.11, WordPress 6.9/7.1.1, with a non-default `uop_ci_` prefix. Artifact smoke uses the default prefix.
- After browser testing, each matrix entry converts its disposable installation to Multisite and runs `tests/multisite.php`: subsite prefix, distinct migration locks, independent schema/state, repeat activation, correct-site cache invalidation when the caller switches sites during a transaction, and preservation of the main site's schema/seed.
- Multisite testing validates site-local persistence only; it does not implement network-wide product features.
- Quality gates include PHPCS, PHPStan, ESLint, dependency audits, exact manifest/specification comparison, reproducible packaging and installation of the actual artifact.

Completed CI evidence is recorded in PR #1 for the tested head commit. The release version is `0.1.0-alpha.2`; schema/data version remains 1.
